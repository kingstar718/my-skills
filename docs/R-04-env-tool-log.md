# 工具失败日志检索与闭环

**状态**：待回归

## 背景与范围

会话中出现重复读取规则、切换数据目录、修复后记录仍为 OPEN 的情况。
现有查询默认排除已修复记录，复发去重读取最早记录，教训生成仅统计词频。
本次收敛使用规则，修复日志检索、复发去重和教训生成。

- **范围**：env-tool-log 入口、引用说明、UI 元数据、失败日志脚本及测试。
- **非目标**：不安装 hooks，不清理本机日志，不修改插件缓存或升级版本。
- **关联需求**：沿用[需求(R-01)](R-01-skill-workflow-refactor.md)的文档约定；
  本次不替代该需求的行为规则。

## 验收标准

- **验收标准(AC-1)**：会话首次使用某工具或环境变化时查看相关经验，覆盖 shell、文件读取、搜索、补丁、浏览器与 MCP 等内置工具；
  会话内复用已确认信息，固定数据目录，不为普通命令重复探测。
- **验收标准(AC-2)**：预期红灯、搜索无匹配和业务断言不进入工具失败日志；
  可复用的工具、环境问题在失败时记录，验证修复后关闭，日志工具故障不递归记录。
- **验收标准(AC-3)**：当按解决方法检索时，`query --all` 应匹配 `fix`；
  默认查询仍只返回 OPEN，保留现有 hooks 和 CLI 调用方式。
- **验收标准(AC-4)**：同签名只维护一条当前记录，复发时更新次数、最近时间和状态；
  归档记录复发时恢复原记录，不追加副本。修复方法原位更新，关闭不删除预防规则。
- **验收标准(AC-5)**：教训按工具分类，包含稳定签名、触发条件与已验证做法；
  复发时保留已验证方法并标明待复核，不把新候选方法当作已验证。
  增加错误和关闭时同步索引，保留手工正文，完整索引不截断为最近几条。

- **验收标准(AC-6)**：默认目录为 `~/.my-skills/env-tool-log/`，显式环境变量优先；
  快照与各客户端 hooks 使用同一解析，来源通过 `from` 区分。
- **验收标准(AC-7)**：若旧 `.codex` 目录中存在数据，则默认调用应向 stderr 提示迁移选项，
  单进程最多提示一次，不修改、搬移、合并或读取旧数据；stdout 格式不变。
- **验收标准(AC-8)**：技能 description 使用中文，入口与引用一致描述共享目录及兼容方式。

## 关键设计

- **查询**：新增搜索 `fix`，保持默认 OPEN 和 `--all` 的既有语义与结果顺序。
- **去重**：签名忽略首尾空格与大小写；同签名原位更新，命中旧重复数据时仅合并该签名。
  不按模糊错误文本自动合并不同原因，不批量改写本机日志。
- **教训**：使用记录中的签名、原因和修复方法，不推断未经验证的通用结论。
  自动区块使用注释边界，旧版未标记的词频正文不擅自删除。
- **客户端边界**：hooks 自动捕获无法识别全部预期红灯；
  使用方需核对误记，未执行的修复不能被标记为已验证。
- **文档归位**：快照与失败日志说明合并到 `references/data-and-usage.md`，
  删除原两份说明；工具调用规则继续独立维护，脚本与运行行为不变。
- **目录兼容**：默认目录独立于客户端；旧数据仅提示，迁移前可显式配置旧目录。
  不改写各 harness 的环境配置。CLI 的默认来源 codex 保留兼容，手工调用显式传入来源。
