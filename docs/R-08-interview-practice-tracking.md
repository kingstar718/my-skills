## 背景与范围

`interview` 技能的练习侧规则与 interview-wiki 仓库里实际运行的记录方式已经分叉：
技能要求维护 `log.md` / `profile.md` 个人档案，但 43 次练习提交中没有产生这两份文件；
用户真正使用的是 `content/个人记录/刷题进度.md` 的勾选与「错题本」表，
以及 `practice/README.md` 的套路速查表。两套记录并存导致重复维护与计数漂移。

本轮把技能的档案机制改为复用仓库既有记录，并补上与仓库约定的对齐：

| 现状问题 | 处理 |
| --- | --- |
| `log.md` / `profile.md` 空转 | 移除，改用错题本表与进度勾选 |
| `practice_dir` 写死 `D:\` 盘符、`刷题进度.md` 路径写错 | 改为相对内容库根的三个配置字段 |
| 技能写死「本机 JDK 8」、README 写死「JDK 21 单文件模式」 | 改为运行时探测 |
| 速查表与 ✅ 全靠手改，出现 37/39、15/13 等漂移 | 新增 `practice_stats.py` 生成与校验 |
| 提交消息格式未定义 | 沉淀「交付/收口」两种模板 |
| 声明对 wiki 全程只读，但 practice 与进度文件都在 wiki 内 | 改为按目录划分写入边界 |

范围仅限 `interview` 技能的练习侧指令、`references/library.md`、`references/learning-progress.md`、
`references/submit.md` 与新增的 `scripts/practice_stats.py` 及其离线测试。
出题、讲解、八股与模拟面试流程不变；`my-skills` 之外只有本机安装副本需要重装。

## 验收标准

- **验收标准(AC-1)：档案单一真源**
  - 技能不再创建 `log.md` / `profile.md` 或其他平行档案。
  - 开场读取错题本与未勾选题；收口追加错题本一行并更新状态列。
  - 旧档案若已存在，只读兼容，不迁移、不双写。
- **验收标准(AC-2)：路径不写死机器**
  - `practice_dir`、`progress_file`、`index_file` 三个字段均相对内容库根，`SKILL.md` 不出现盘符。
  - 缺少内容库时按既有寻址顺序回退，不因路径配置失败而中断练习。
- **验收标准(AC-3)：统计可校准**
  - `practice_stats.py --check` 能以进度勾选为真源报出速查表、✅ 标记与（N / M）的偏差，有漂移退出码 1。
  - `--fix` 只重写速查表、✅ 标记与计数，不新增题目行、不改正文；`--dry-run` 打印 diff。
  - 已做但缺索引行的题目单独报告，不静默计入合计。
- **验收标准(AC-4)：运行方式与提交约定**
  - JDK 版本按 `java -version` 探测：≥11 用单文件模式，8 用 `javac + java`，两者都不可用时给出兜底。
  - 静态内部类、多版本同文件、Solution 临时产物三条硬约定写入 `SKILL.md`。
  - 收尾三步与「交付/收口」提交模板明确，默认不 push。

## 关键设计

- **记录本体在仓库**：`progress_file` 的勾选是「哪些题做完」的唯一真源，错题本是「卡在哪」的档案；
  技能只读写这两处，不再引入第三份记录。
- **路径相对化**：三个字段相对内容库根，`library.md` 只回写 `local_dir` / `git_url`；
  `local_dir` 的取值仍由用户决定，本轮不改本机既有配置。
- **分母来自索引**：套路速查表的分母取该章节现有题目行数，因此「已做但索引缺行」会显式暴露为差异，
  而不是把总数改小掩盖问题。
- **脚本保守写入**：`--fix` 不生成题目行、不调整章节归属；`--fix-list` 保留已有顺序、只追加漏项并更新日期。
- **写入边界**：题库正文（`content/algorithms/`、`content/interview/`）只读；
  允许改 `practice/` 下的练习文件、进度勾选与错题本行、索引里的 ✅ 与计数三类。
- **版本**：四份组件版本同步升级为 `2.0.7`。
