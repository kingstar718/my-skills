## 背景与范围

技能名称用于表达用途，仓库名 `my-skills` 表达集合归属。
本轮移除六个入口中的个人前缀或冗长后缀，博客随记保留 `blog-` 归属；
将 `cn-writing` 改为 `content-write`，涵盖文本内容的编写、整理与审阅。
通用表达、语言和格式规则分别标明适用范围，其他技能行为、执行授权和个人数据约定继续有效。

| 原入口 | 当前入口 |
| --- | --- |
| `git-commit-convention` | `git-commit` |
| `my-blog-build` | `blog-publish` |
| `my-note-publish` | `blog-note-publish` |
| `my-interview` | `interview` |
| `my-learn` | `learn` |
| `my-statusline` | `claude-statusline` |
| `cn-writing` | `content-write` |

`env-tool-log` 和现有 `code-` 入口保持原名。
本轮不合并技能，源码随 `2.0.6` 提交发布；本机副本另行更新。

## 验收标准

- **验收标准(AC-1)：入口一致**
  - 七个目录、`SKILL.md` 的 `name`、正文标识及已有 UI 提示应与映射一致。
  - 旧名称不再作为兼容技能分发，默认提示显式引用当前 `$skill-name`。
  - 跨技能链接和调用名称应同步，两个学习入口保持独立职责。
  - `content-write` 应用于文章、随记、说明、文案和 Agent 指令；中文及 Markdown 专用规则仅在对应语言和格式下生效。
- **验收标准(AC-2)：数据兼容**
  - 随记配置继续使用 `~/.config/my-note-publish/config.json` 及已有环境变量。
  - 面试继续使用既有 Cookie、内容库缓存与学习工作区，不因入口改名建立空档案。
  - Claude Code 状态栏继续使用 `~/.claude/statusline.js`；工具经验与通用学习数据位置不变。
  - 用户数据目录中的旧字符串表示兼容路径，应保留并说明，不作为失效入口删除。
- **验收标准(AC-3)：客户端与文档**
  - Pi 应排除 `claude-statusline`，保持11个源码入口、10个通用入口。
  - README 应说明完整迁移映射和显式安装方式，区分通用技能与 Claude Code 专用技能。
  - 历史规格的旧名称应能定位迁移规则，失效的源码链接应指向实际新路径。
- **验收标准(AC-4)：验证边界**
  - 技能结构、现有 UI、清单、引用及实际发现集合应可检查且无重复入口。
  - 移动后的确定性发布脚本应通过已有离线测试，数据默认路径与脚本行为保持一致。
  - 学习 HTML 的内容和逻辑不随改名变化，示例文案与显示名称使用当前入口。
  - 本轮源码检查不能证明本机安装、真实登录、线上发布或教学效果已验证。

## 关键设计

- **迁移范围**：七个源码目录原位改名，所有运行时引用同步；不提供旧名包装或重复副本。
- **内容规范**：表达、结构、语义与信息层级作为通用规则；中文排版和 Markdown 语法按条件使用。
  保留已有正文与 Agent 文档参考，不为改名重建一套平行规则。
- **兼容位置**：配置、Cookie、缓存和练习目录中的旧名称保留。
  既有脚本不改默认存储位置，不新增凭据迁移和用户确认流程。
- **安装说明**：发布含改名的版本后，先安装并检查新入口，再按名称移除旧入口。
  仅移除技能安装副本，不删除个人数据；其他客户端配置中的显式旧引用由使用方更新。
- **影响范围**：技能目录、文档与 Pi 筛选配置；无业务 API、数据库或外部服务契约变化。
- **版本**：四份组件版本同步升级为 `2.0.6`，本次提交包含七个入口改名与内容规范适用范围调整。

- **静态检查**：11个技能通过 `quick_validate.py`，目录与 frontmatter 名称一致；
  现有 UI 默认提示使用对应新名称，5份 JSON 清单可解析，四份组件版本同步为 `2.0.6`。
  七个目录的原文件均完整迁移；运行时旧名称只保留在明确兼容的数据路径中。
- **脚本验证**：在新目录运行 `python -m unittest discover -s plugins/my-skills/skills/blog-note-publish/scripts -p 'test_*.py' -v`，
  16个用例通过。首次沙箱执行在临时目录写入阶段失败，取得所需执行权限后同一命令通过，未修改测试或业务脚本。
- **规则走查**：`content-write` 的通用表达、中文规则和 Markdown 规则有明确适用范围；
  英文内容不强制使用中文标点，HTML 或纯文本不强制使用 Markdown 语法。
  此项为指令检查，不代表独立模型已完成各语言与格式的行为回归。
- **内容边界**：HTML 只更改示例显示名称，未重跑上一需求的浏览器用例；
  本轮通过原版本对比证明脚本与样式一致，不把原浏览器证据说成新一轮执行。
  状态栏逻辑和既有 Python 脚本保持原样，未进行真实登录、线上发布或个人档案读写。
- **验证限制**：当前环境未提供 `plugin-creator` 的专用校验器，未执行该检查；
  已检查清单和实际 Pi 解析，不等同所有客户端均已安装或加载新版。
- **待回归**：实际客户端迁移、历史个人数据读取、不同语言与格式的内容生成及后续真实业务使用。
  本轮源码随 `2.0.6` 提交发布，未修改安装目录、用户配置与个人档案；实际客户端迁移仍待执行。
