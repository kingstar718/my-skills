## 背景与范围

早期 `spec-coding` 将状态、需求、设计、任务、TDD 和回归强制放在单文件，容易让中大型需求不断
膨胀；`spring-testing` 又把通用测试原则、特定项目模块结构和 lbs-cloud 个案混在一起。本需求重构
测试职责和交接格式，并补充连续迭代及中文写作约定，为本仓库建立精简的文档入口。

范围包括：

- 维护仓库文档入口、需求登记表和单文件模板。
- 调整 `spec-coding` 的流程、模板、示例和 UI 元数据。
- 调整 `spring-testing` 的分层决策、基础设施边界和条件性参考资料。
- 补充 `spec-coding` 连续迭代审阅、文档更新职责及验证范围，
  由 `cn-writing` 统一中文 Markdown 源码换行规范。
- 检查客户端元数据与基础版本一致；本轮不升级版本或发布插件。

不包括：迁移使用这些 skill 的其他仓库文档；自动安装或发布插件；合并两个 skill。

- 涉及范围：spec-coding、spring-testing、cn-writing、模板、UI 提示及研发文档入口。
- 关联需求：
  - 与[需求(R-02)](R-02-local-note-publish.md)共享中文写作规范，不修改其发布协议。
  - 与[需求(R-03)](R-03-pi-package.md)共享插件元数据范围，本轮不改其清单或版本约定。

## 验收标准

- 验收标准(AC-1)：新需求默认用单份 Markdown 维护规则、设计要点和验证结果。
- 验收标准(AC-2)：不主动建立目录或拆分文件；只有用户明确要求，或某部分确需独立维护时才拆分。
  接口文档可独立，遵循仓库已有约定，既有目录仅在明确要求时迁移。
- 验收标准(AC-3)：当编写验收标准，系统应要求每个验收标准有可追溯的验证覆盖；若一个验收标准需要多层测试，
  则不强制它与单个单元测试一一对应。
- 验收标准(AC-4)：当 Spring 任务需要验证业务协作，`spring-testing` 应允许 mock 外部依赖；当验证
  SQL、Redis/Lua、消息协议或驱动行为，则应使用足够真实且隔离的基础设施。
- 验收标准(AC-5)：当选择测试位置和环境，`spring-testing` 应优先遵循仓库结构和被验证行为，不把
  `core/web`、真实 Nacos 或 Testcontainers 作为所有项目的硬约束。
- 验收标准(AC-6)：当 E2E 目标环境不可达，则本地可显式跳过；若该环境是 CI 或发布门禁的必备目标，
  则测试应失败而不是假绿。
- 验收标准(AC-7)：当普通需求完成，则不要求更新 `AGENTS.md`；只有长期仓库规则或入口变化时才更新。
- 验收标准(AC-8)：当两个 skill 协作，`spec-coding` 应管理验收标准与证据映射，`spring-testing` 应细化
  测试层级和实现方式，二者保持独立触发。
- 验收标准(AC-9)：当完成本次修改，则两个 skill 和插件 manifest 应通过结构校验，Codex 与 Claude
  Code manifest 的基础版本保持一致。
- 验收标准(AC-10)：当同一需求持续调整，`spec-coding` 应原位更新当前规则，按职责选择更新文档，
  索引不复制测试数量或命令；每轮说明局部变化，不新增例行确认关卡。
- 验收标准(AC-11)：当记录验证，则应集中标明覆盖范围、版本或改动范围及未核实假设，
  不以局部单测结果声称全量通过或实际展示已验证；验收句式使用「当、应、若、则」，
  模板与示例保持一致。
- 验收标准(AC-12)：当编辑中文 Markdown，`cn-writing` 应建议按语义控制源码行宽，
  保留语法及标识符完整，遵循仓库配置且不重排无关段落。
  有先后用有序列表，并列用无序列表；父项概括与子项细则分开，`spec-coding` 引用该规范。

- 验收标准(AC-13)：登记前应按涉及范围检查已有需求，并说明实际关联。
  若替代既有规则，则应明确替代条目与适用范围；未解决的冲突应列为待确认项。

## 关键设计

默认一份需求 MD，规则、设计要点与验证结果在本文原位更新。
本需求按用户要求从目录合并；历史交给 Git，不保留多份当前结论。

| Skill | 职责 | 交接方式 |
| --- | --- | --- |
| `spec-coding` | 需求、验收标准与证据覆盖 | 关联用例和验证结果 |
| `spring-testing` | 按风险选择测试层级及实现 | 返回用例、层级与外部依赖 |
| `cn-writing` | 中文行文、语义换行与列表层级 | spec-coding 引用同包规范 |

`SKILL.md` 保留决策规则，模板与示例展示记录方式。
Spring 切片、集成、E2E 和框架特例沿用原有参考文件，按任务读取。
三个 skill 保持独立；本轮只同步 spec-coding 的 UI 提示，不修改安装缓存或发布插件。
