# 代码审阅

固定实际改动范围，分别检查代码质量与需求符合度，用可追溯证据报告发现。
审查、交付说明、工程复盘和代码任务交接按请求选择，不默认执行完整收尾流程。

## 代码审查

1. **确定范围与依据**
   - 用户指定分支、提交或路径时沿用；否则检查当前工作区、暂存区与相关未跟踪文件。
   - 分支比较选用能表达任务范围的基线并记录依据；`HEAD` 的比较不代表包含未提交内容。
   - 读取仓库规则、涉及调用链、起始需求及最新决策；差异为空时报告，不生成虚构发现。
   - 完成条件：基线、实际差异和可用需求依据明确；无规格时说明需求审查边界并继续代码检查。
2. **分别核对两个角度**
   - **代码质量**：正确性、边界、错误传播、资源与并发行为、职责和调用方兼容性。
     风格遵循仓库规则；可能的重复或职责问题先核实调用链，不把重构偏好当缺陷。
   - **需求符合度**：逐项核对行为、输入约束、非目标与关键决策，检查遗漏及额外改变。
     对照实际测试与证据范围，不把未运行的测试或 mock 结果当作外部行为已证实。
   - 需要验证方法或诊断时使用可用的 `code-test`；缺失时沿用项目既有约定。
3. **报告发现**
   - 按影响排序，给出具体位置、触发场景、后果、证据和最小修正建议。
   - 区分已确认问题、待核实风险与验证缺口；同一根因合并报告，避免用数量代替价值。
   - 未发现问题时直说，并列出实质未验证范围；完成条件是结论能够回到差异或证据核查。

用户只要求审查时，返回发现；修改、暂存、提交或推送按已有明确授权执行。
本技能不因审查完成自动调用 Git 提交或扩大实现范围。

## 交付说明

- 先说明具体问题与变更后的行为；按改动需要给出前后测试、输出、截图或简图。
- 写明实际验证、影响范围、兼容性与回退难度；简单改动用简短文字即可。
- PR 正文遵循项目模板，描述最终实现；已有规格与证据用链接引用，不复制对话历史。
- 写交付说明不等于发布；提交消息使用可用的 `git-commit` 或仓库规范。

## 可选分支

- **工程复盘**：用户要求复盘工程过程或改进 Agent 工作环境时，
  读[工程复盘](references/retrospective.md)，将发现归入检查、规则、导航或工具经验。
- **代码任务交接**：用户要求换会话、换 Agent 或交接当前代码任务时，
  读[代码任务交接](references/handoff.md)，保存继续工作所需的状态与引用。

审阅报告与交付说明使用可用的 `content-write`；其缺失时沿用项目写作规范。
