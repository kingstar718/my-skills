# 工程复盘

只在用户要求工程复盘或改进 Agent 工作过程时使用，不把面试学习复盘路由到此处。

1. **读取实际过程**
   - 用户指定会话时读取相关证据；否则使用当前会话与改动，不默认扫描全部历史日志。
   - 对照目标、实际行为、关键返工和验证缺口，区分偶发事件与可复用问题。
2. **找最小改进落点**
   - 导航困难：修正已有入口及引用触发，而不是复制整份资料。
   - 机械错误：检查已有 lint、测试、脚本或 CI 是否生效，优先复用确定性检查。
   - 判断失误：在对应技能或仓库约定原位修正规则，并说明适用场景。
   - 工具与环境失败：交给可用的 `env-tool-log` 维护同一签名及已验证预防方法。
   - 无效要求：删除失效、重复或没有改变执行行为的文字，保留必要约束与原因。
3. **提交可审阅的建议**
   - 说明现象、证据、影响、建议位置及如何观察改进，按价值排序。
   - 区分已验证原因与候选解释，不把一次项目特例变成全局规则。
   - 用户只要求复盘时给建议；已授权修改时再落实相关内容，不自动添加 hooks 或 CI。

完成条件：重要问题有证据与明确归属，已有同类规则已核对；未执行的改进不报告为已生效。
