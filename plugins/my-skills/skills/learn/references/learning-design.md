# 学习设计

用于新主题调研、组织知识联系，以及需要依据表现调整练习的场景。
目标与本轮步骤见[技能入口](../SKILL.md)，个人证据按[档案规则](learning-state.md)保存。

## 资料与学习目标

- **可观察目标**：把「学会并发」收敛为当前想独立完成的任务，例如解释阻塞、调整线程池或排查积压。
  不强制所有主题采用编程题；设计、语言或操作技能使用相应作品、表达或实践结果。
- **研究范围**：先回答当前课程的问题，再逐步扩展；已有可靠资料可复用。
  技术事实优先官方文档、规范、源码或原始研究，实践步骤可用可信的一手示范。
- **来源判断**：核对版本、适用条件及必要的前置；资料冲突时指出口径差异。
  将来源支持的事实、教学简化、推断与未知项分开，生成题目的答案也应有依据。
- **资料不可得**：说明哪些结论尚未核实，缩小课程范围或提供明确标注的暂定解释。
  不编造引文，也不因穷尽资料而推迟已可可靠教授的内容。

## 知识联系

围绕当前目标保留必要概念，使用文字、关系表或小图表达。
每条联系说明关系与例子，不将相邻排列视为已经建立理解。

| 关系 | 应说明的内容 | 队列学习的示例 |
| --- | --- | --- |
| 前置 | 学当前内容需要先理解什么 | 理解处理能力后，才能判断任务是否积压 |
| 因果 | 条件变化通过什么机制影响结果 | 到达量持续超过处理量，会增加等待任务 |
| 对比 | 相似概念在哪个条件下产生不同结果 | 有界队列会触发满载策略，无界队列会继续积压 |
| 迁移 | 已知方法怎样用于新情境及其限制 | 用供需差理解线程池积压，但真实任务耗时并不恒定 |

发现一个缺口时沿前置关系回查，不把整个领域图都当作必修目录。
用户已有知识可作为解释桥梁，类比同时标出失效之处。

## 任务选择与难度

练习类型按目标与表现选择，下面的顺序是参考，不是固定晋级考试。

| 任务 | 要观察的能力 | 调整方式 |
| --- | --- | --- |
| 解释、辨别 | 能否说清机制与易混边界 | 换例说明；区分概念记错与表达不清 |
| 预测、操作 | 能否在反馈前判断结果并控制变量 | 先预测再运行，比较预期和实际 |
| 独立完成 | 能否在缺少提示时完成目标任务 | 逐步撤掉支架，验证关键边界 |
| 排错、迁移 | 能否识别失败原因并用于新场景 | 更换约束、表示方式或场景，避免只改数字 |

- **适量加难**：独立完成且解释成立时，增加一个关键变化；成功标准随任务说明。
  用户自述轻松可用于选题，但晋级结论仍需实际表现支持。
- **支持递减**：卡住时先给方向或局部提示，再按需要给示例；记录提示发生在作答前还是作答后。
  已展示完整答案后，后续同题重答作为练习，独立验证换一道题。
- **反馈时机**：练习模式及时解释原因；用户要求测验时先收齐约定范围的答案再反馈。
  避免题干、选项长度和位置规律暗示答案，不强求所有选项字数完全相同。
- **开放任务**：先说明评价维度，依据真实回答、作品或运行结果反馈。
  缺少观察条件时标为待评或用户自报，不把按钮点击视作实际操作已完成。

## 补短板与复习

| 观察 | 先核实 | 针对处理 |
| --- | --- | --- |
| 术语熟悉但解释矛盾 | 概念是否混淆 | 用反例辨别，再让用户重述机制 |
| 当前步骤反复卡住 | 必要前置是否缺失 | 补最小前置，再回到原目标 |
| 原理正确但执行失败 | 工具、操作或实现细节 | 缩小操作步骤，用实际结果定位 |
| 原题正确、变式失败 | 方法适用条件与迁移 | 比较两种情境，说明何时换方法 |
| 当场完成、隔天忘记 | 回忆是否依赖刚看过的提示 | 安排不看答案的延迟回忆，再调整间隔 |

以上是诊断线索，单次错误不足以确定根因。
每轮优先解决影响当前目标的缺口，不同时追问所有短板。
把辅助完成、独立完成、迁移和延迟保持分别记录；未观察到的能力保持待验证。
复习间隔随表现调整，不设对所有主题统一有效的天数或熟练百分比。
