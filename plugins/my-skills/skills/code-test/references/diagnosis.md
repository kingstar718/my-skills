# 故障诊断循环

适用于功能错误、间歇故障与性能回归；已明确的简单错误可直接采用最小复现与回归。
证据回填已有任务记录，不额外建立完整日志体系。

1. **建立失败信号**
   - 明确预期与实际、受影响版本、输入和触发条件；先复用用户提供的日志或请求。
   - 按适用性选择失败测试、HTTP 或 CLI 重放、浏览器脚本、脱敏轨迹回放、最小程序。
   - 完成条件：能针对该故障判定失败；暂不能复现时，记录已观察事实与下一步采证方式。
2. **缩小范围**
   - 对照已知正常版本、最小输入和运行配置；必要时二分提交或比较新旧输出。
   - 缩短反馈周期，控制时间、随机性与共享数据；保留足以解释差异的日志与调用链。
3. **验证假设**
   - 每个假设写清可预测的观察信号，尽量一次改变一个关键因素。
   - 用定向日志、计时、计数或隔离替身区分竞争原因，记录支持与否定证据。
   - 完成条件：证据能解释症状并排除主要替代原因；推测与已证实根因分开报告。
4. **最小修复与回归**
   - 修正证据指向的职责位置，复用最初信号验证前后差异，必要时补相关回归用例。
   - 原问题未能复现或环境不可达时，说明修复依据与验证边界，不把「未再次出现」等同根因已证实。
   - 临时日志和诊断代码按必要性保留或清理，最终交付列明剩余风险。

所有输出与保存产物应脱敏；对共享或生产环境的采集、重放及变更遵守已有授权范围。
可复用的工具、参数或环境故障交给可用的 `env-tool-log` 按签名维护；
业务故障的假设与验证证据留在任务中，不把预期测试红灯登记为工具故障。
