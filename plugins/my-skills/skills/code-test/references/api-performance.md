# 接口与性能验证

## 接口契约

- 先明确真实入口、认证方式、输入约束、状态码及序列化结构，复用仓库已有契约用例。
- 对关键正常路径、空值、非法输入和错误传播验证调用方可观察的行为；
  框架切片证明绑定与映射，跨进程测试证明部署后的实际协议路径。
- mock 远端只能证明本地协作，真实协议兼容或中间件语义需要隔离环境证据。
- 重放真实请求时移除密钥和个人数据，使用明确允许的测试目标与可清理数据。

## 性能证据

先明确要回答的是耗时回归、吞吐、容量还是资源瓶颈，再选择测量方法。

1. **定义可比条件**
   - 记录数据规模、请求分布、并发或到达率、运行环境、依赖和预热方式。
   - 明确成功率、错误率、延迟分位数与资源指标；容量测试需有可接受阈值和停止条件。
2. **测量与比较**
   - 使用项目现有基准或负载工具，在相同条件下比较前后结果。
   - 分开观察客户端排队、服务耗时、下游等待、CPU、内存及连接池。
   - 容量或压力测试仅针对已授权目标；日常排障优先只读指标与窄范围复现。
3. **限定结论**
   - 报告样本、时间窗口、实际负载、延迟分布、错误与资源情况。
   - 平均耗时不能单独推出最大吞吐量；历史每分钟请求峰值只是已观察负载。
   - 发现增长拐点或退化时，按[诊断循环](diagnosis.md)验证瓶颈假设。

没有实际测量时只给估算依据与待验证项，不用单测或代码分析声称容量已验证。
