# 面向 Agent 的文档

适用于技能入口、仓库指令和 Agent 按引用读取的执行资料。
表达、结构及语言与格式规则沿用 [content-write](../SKILL.md)，按实际内容选择适用规则。

## 引用与信息层级

- **引用条件**：指明何时读、资料解决什么问题、入口在哪里。
  例如「处理 Spring MVC 切片装配问题时，读 slice-tests.md 排查上下文隔离」。
- **共同规则**：所有适用分支都需要的判断留在入口；只有部分场景使用的细节放引用。
  简短且自足的技能可以只有一个文件。
- **概念归位**：定义、适用条件和例外放在相邻位置；同一要求只维护一份正文，其余位置引用。
- **入口精简**：description 写任务与触发条件；同义关键词合并，不罗列全部实现细节。
  先修正引用措辞，再考虑把被遗漏的资料搬到入口。
- **环境事实**：命令、目录和版本能从当前配置或帮助查明时直接查明；
  文档保留不易发现的约定、选择原因和已验证陷阱。

## 步骤与完成条件

步骤写动作及其可观察结果，参考规则按主题并列；列表层级沿用主规范。
只有存在结束判断的步骤才补完成条件，不给每句话套格式。

| 模糊写法 | 可检查的写法 |
| --- | --- |
| 充分理解需求 | 列明目标、输入边界和影响实现的未决项 |
| 测试通过后结束 | 指定用例实际执行且通过，说明未覆盖的外部行为 |
| 确认引用无误 | 引用路径存在，触发条件与目标资料范围一致 |

简单任务不强制经历完整流程；分支结束即可返回所需结果。
执行授权和事实证据分开描述，避免将「能执行」写成「已获准执行」。

## 更新与复验

- **原位修改**：补缺口、删除失效规则；不按对话轮次追加近义要求。
- **正向表达**：优先写目标行为；确需禁止的操作同时给出可用做法或停止条件。
- **行为核对**：用一个适用场景和一个相邻的不适用场景检查入口，
  观察是否读到正确资料、是否引入无关流程；结构校验只证明格式与引用。
- **保留差异**：规则复用项目约定；不为格式统一复制不同项目的环境与目录配置。
